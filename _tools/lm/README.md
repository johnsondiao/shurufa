# 字符级 bigram 语言模型（阶段 4b）

给九键**整句候选**提供词间上下文：决定「说得好 vs 说的好」「在哪 vs 在那」这类
**同音歧义**——两条路径的每个词 unigram 分数完全一样，只看词频永远分不出来。

## 为什么是字符级，不是词级

| | 字符级 bigram | 词级 bigram |
|---|---|---|
| 组合空间 | ~8000 × 8000 | 38 万 × 38 万 |
| 语料需求 | 千万字级即可稳定 | 语料再大也极稀疏 |
| 体积 | 3.2 MB（剪枝+量化后） | 数十 MB 起 |
| 精度 | 略低，但覆盖全 | 高，但只覆盖常见搭配 |

因为整句 DP 只需要给**词与词的搭接处**打分（词内部已由词的 unigram logp 表达），
字符级刚好够用，且体积可控。

## 语料

| 来源 | 句数（采用） | 字数 | 语体 |
|---|---|---|---|
| Leipzig `zho_news_2020_300K` | 220,475 | 883 万 | 书面新闻 |
| OPUS OpenSubtitles v2016 zh | 2,731,306 | 2,200 万 | 口语对话 |
| OPUS wikimedia | 214,407 | 1,556 万 | 百科 |
| **合计** | | **4,549 万字** | |

三种语体混用是有意的：只用新闻，口语里的「在哪 / 干嘛 / 好的」统计会很弱；
只用字幕，术语型搭配又会被稀释。

## 用法

```bash
# 1. 下载语料（幂等，已存在则跳过；合计约 300 MB）
python fetch_corpus.py

# 2. 构建模型 -> bigram.db
python build_bigram.py

# 3. 评测收益（离线，不改动 APK）
python ../eval/sweep_bigram.py --lm bigram.db
```

字符集（`charset.txt`）从 `base_words.db` 自动推导：只统计词库里真的出现过的 CJK 字，
避免日文假名/繁体外字/生僻符号的噪声共现混进模型。

## 打分方式

Dirichlet（加 δ）平滑，δ = 0.6：

```
P(b|a) = (c(a,b) + δ·P_uni(b)) / (c(a) + δ)
```

相比纯 MLE + Stupid Backoff，好处是**见过的组合恒优于没见过的**——
SB 下罕见但见过的组合会输给没见过的，排序会抖。

剪枝后未保留的 `(a,b)` 用**精确**退避，不是近似：

```
P_backoff(b|a) = δ·P_uni(b) / (c(a) + δ)
               = exp(logp_uni[b] + norm_logp[a])
```

`norm_logp[a] = ln(δ/(c(a)+δ))` 随 `char_uni` 表一起存下（随时可整体载入内存）。

**中心化**：每个边界项都减去 `mean_logp`（语料上边界对数概率的期望 ≈ −H(字符)，
本模型为 −6.584）。不做这一步，`Σ 边界项` 会随分段数线性变负，等于塞进一个
与 β 耦合的长度惩罚——整句候选会被单词条挤空，且 β 一个旋钮同时控制
「上下文强度」和「偏向长词程度」，无法独立调参。

## 模型结构

```sql
char_uni(cp PK, logp, norm)     -- 6660 行，整表载入内存
bigram(prev, next, logp PK)     -- 133,676 行，整表载入内存
lm_meta(key, value)             -- delta/min_count/top_n/mean_logp/...
```

设备端不查 SQL，而是把两张表压进一个开放寻址的 long→int 表（约 3 MB，查询零分配）。
整句 DP 一次要查几千次边界分，走 SQLite 会成为单键延迟的主要来源。

## 参数

| 参数 | 取值 | 说明 |
|---|---|---|
| `delta` | 0.6 | 平滑强度 |
| `min_count` | 3 | 计数低于此值的 bigram 丢弃 |
| `top_n` | 48 | 每个前字最多保留多少个后继 |
| `per_source_chars` | 22,000,000 | 单条语料吸收上限（控制内存/耗时） |
| `min_in_charset_ratio` | 0.75 | 行内"字集合命中率"低于此判为繁体/日文 |

## 实测（473 条评测语料，综合口径）

| 配置 | Top-1 | Top-5 | 可达率 | 平均位次 | MRR | 整句路径 Top-1 |
|---|---|---|---|---|---|---|
| 无语言模型（阶段 1） | 86.4% | 98.3% | 98.9% | 1.86 | 0.918 | 15.5% |
| **bigram（β=0.6, 段罚=1.5, K=8）** | **87.1%** | 98.9% | **99.6%** | **1.48** | **0.924** | **27.5%** |

整句路径 Top-1 相对提升约 **77%**，是本次改动收益最集中的地方。

## 已知局限

- **同音虚词仍分不干净**：`说的好` 仍排在 `说得好` 前（`P(的|说) > P(得|说)`，
  语料里「说的」确实更常见）。要彻底解决需要 trigram 或词级上下文。
- **俗读缺失**：`做什么` 需要 `么 → mo`，这是词库读音问题，不是语言模型问题。
- **未做个性化**：目前只有一个通用模型。按 OVERHAUL_PLAN 的调研（SwiftKey 4.6% vs 5.7%），
  个性化语言模型还有明显空间，属于阶段 5。
